01

cat architecture.md

MINT runs a local-first research infrastructure on a Mac Studio. FeedMe reads hundreds of sources three times a day and ranks what matters to the lab. Yesterday in AI is written from its shortlist, with Seth choosing and approving every issue. A searchable paper corpus, with its own paper-fetching and review services, sits behind the lab's Slack agents and a read-only server for collaborators' assistants. Shared services handle credentials, model access, backups and the public route in. Public pages are static files deployed through GitHub Pages.

02

trace content-pipeline

FeedMe is the shared collection and ranking layer. The full 04:00 run starts all seven fetchers at once, drops repeats and stale items, scores every new item against the lab's interest profile, summarizes long pieces, and groups the survivors into stories on the day's slate. The 12:00 and 20:00 runs are top-ups with six fetchers that merge new stories into the same slate. Items count as seen only once the slate accepts a run, so a failed run is fetched again. A watchdog checks the morning run thirteen times before 08:00 and restarts it if it stalls.

Source adapters

X timelines
BirdClaw reads the followed and recommended timelines through a signed-in session, with fallbacks when a live read fails. It expands busy conversations into threads, stopping at the first refusal or rate limit, and fetches the full text of articles that short posts point to.
Bluesky feeds
An authenticated AT Protocol client reads five feeds and expands threads before writing normalized items.
Feeds, journals and podcasts
About 380 web feeds, journals and podcasts are read each run, keeping recent unseen entries. Journals get longer windows and a cap on new articles, and the morning run adds podcast captions. A weekly source finder reads roundup posts and adds high-confidence recurring sources.
Newsletter inbox
The Gmail API reads newsletter mail from a dedicated inbox, strips tracking, and filters out account and promotional mail. Full text for cut-short or paid articles comes through web requests or signed-in browsers, including the university library.
arXiv
New paper listings are read every run, dropping papers already seen. Each paper gets its authors and institutions, and paper posts by trusted researchers are marked to pass scoring.
PhilPapers
The morning run reads recent PhilPapers additions alongside arXiv, across the lab's philosophy and technology-ethics categories.

Products and agents

Yesterday in AI
Seth marks stories on the day's slate in the curator app. An evening selector chooses about forty sources and checks each against earlier issues; a 23:00 plan goes to Seth's pitch room, and nothing is written until Seth approves it. Agents then write the digest, research and edit the Read mores, and send Seth a preview. Only an approved issue is published on the website, emailed once to each subscriber, and linked in #mint-community.
Slack picks
After the morning run, two model passes narrow the passed items to a varied 20 to 25, which are posted to #firehose with full-text summaries. Links shared by Seth and lab members are scored and posted there too.
Corpus Agent
news-pdf-bot fetches papers linked in #firehose and cross-posts them to #papers, filing a request when it cannot get a file. The corpus pipeline ingests them, and the persistent corpus-agent answers research questions from the corpus through @Minty in Slack.

A sign-in keeper holds the browsers that read paid sites, the university library and X, tests each login at 09:10 and 17:10, and emails Seth when one needs renewing. Each source is judged against its own recent normal, and Seth is told once when an important source fails and once when it recovers.

03

trace corpus-ingestion

Paper ingestion is a queue-backed set of focused services. Papers arrive from the #papers channel, a local intake folder and a shared Google Drive inbox; papers that an ordinary download cannot get are found by a separate fetching service working through the university library. Each paper is fingerprinted so repeats are set aside before any costly work, then identified, converted, embedded and analysed. One writer owns every database change, and the archive keeps the original PDF on Drive and an entry in the lab's Zotero library.

  1. corpus-intake-localWork the local intake folder overnight, every 5 minutes.
  2. corpus-intake-slackTake papers from Slack from 08:00 to midnight, every 10 minutes.
  3. corpus-ingest-handoffHand unfinished work over at midnight and top up the overnight queue.
  4. corpus-analyzeAnswer 41 research questions and write six summaries per paper.
  5. corpus-db-writerCheck each handoff against its archived files, write it, and read it back.
  6. corpus-tidyClear intake copies once the archived copy is confirmed.
A single database writer is deliberate: every change takes the same write lock, and a handoff whose files or passages do not match is refused and kept for a person to settle, so searches only ever see papers that match their archived files.

The corpus contains both PDF-backed papers and sources captured directly from the web as Markdown. Each document is represented at several levels: bibliographic metadata, full text, searchable chunks, embeddings, structured research-question analysis, and hierarchical summaries. Every Sunday the corpus is regrouped into topic clusters, and each paper keeps a list of its ten closest neighbours. The current document embedding policy is Voyage voyage-context-3, 2048d.

Explore the public projection in the Corpus Map. The public map exposes research structure and links, while the working corpus remains on lab infrastructure.

05

query @Minty

Tag @Minty in a lab channel with a question and it offers buttons for a mode and a model. A model rewrites the question several ways, the agent pulls matching corpus papers, and the answer cites only that evidence, with real links added by the program. Long answers and deep reviews arrive as a PDF. Tag it on a paper or PDF and it adds the paper to the corpus instead.

Mode Best use Searches
Fast Search Quick factual or bibliographic lookup Paper corpus
Fast Review A short review of a focused question Paper corpus
Deep Review Substantive literature synthesis, delivered as a PDF Paper corpus
Conversation Follow-up discussion in the thread Paper corpus and thread context
AI governance Questions about AI laws, bills and policies Governance dataset, refreshed daily
Teaching Questions about training models from human feedback Open textbook and course videos
Outside Slack, a read-only corpus server gives Seth's and invited collaborators' assistants eleven search and lookup tools and a set of review skills, from a quick answer to a deep review. Background jobs use the shared model router; the default model is gpt-5.6-sol, with xhigh reasoning for intelligence-heavy work.

10

inspect agent-runtime

Scheduled agents send model calls through a shared router that rotates through the lab's model sign-ins and rests any that hit a usage limit; a probe checks every sign-in every ten minutes without spending a call. Jobs get credentials by name from a signed helper that keeps them out of code and logs. Deterministic services use ordinary code where a model adds no value; research synthesis and judgment-heavy work use higher reasoning effort.

Task class Reasoning effort Typical work
Intelligence xhigh Research, synthesis, review, and complex judgment
Functional high Implementation and bounded operational tasks
Deterministic medium Mechanical checks where a model is still required
Verification is part of the runtime contract: agents must collect fresh evidence before reporting state, preserve concurrent work, and keep credentials out of public artifacts. Agents prepare; Seth approves anything that is published or sent.
