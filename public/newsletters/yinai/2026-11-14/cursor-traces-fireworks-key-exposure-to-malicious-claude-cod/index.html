Cursor traces its marketplace attack to a key exposed by Fireworks

Cursor says a vendor-held key opened a store of historical agent traces, where unredacted credentials gave the attacker access to internal tools and the extension cache.

The Minty Newsroom · Edited by Codex · 14 November 2026 686 words · ~3 min

Cursor’s November 13 investigation update explains how an attacker reached the marketplace that distributed malicious Claude Code extensions in October. An access key Cursor had issued to Fireworks, its training and inference vendor, was exposed by Fireworks, Cursor says. The attacker used it to copy a shared storage bucket, recovered further credentials from historical coding-agent records and reached internal services. The account adds the access route to the tampered extension packages we covered on October 30.

According to Cursor, the read-only bucket contained a limited set of coding-agent traces, mostly from 2025, from sessions outside Privacy Mode that it was permitted to use for model training. Some contained credentials that had not been redacted. Cursor reports API-credential exposure for fewer than 0.01% of customers and trace exposure for fewer than 0.05% of users. Those figures describe different categories and use different denominators. The company says it identified and directly notified the users whose traces were exposed.

The recovered credentials let the attacker access selected software services Cursor uses. Cursor says the data reached through those services included archived non-production source repositories, limited customer-support records and email conversations, usage metrics and contact details, summaries of some agent conversations, and credentials users had sent to its support team. The initial key permitted reading a data store; credentials inside that store opened access to further systems.

On October 29, Cursor says, the attacker used a credential from the exposed internal data to place malicious copies of Anthropic’s Claude Code extension directly in its marketplace cache. Cursor says Anthropic did not publish these copies, the attack did not exploit an Anthropic product vulnerability, and Open VSX, the upstream extension registry, never carried the malware. At most 5,000 users who requested the affected cached versions potentially received the malicious build during approximately 11 hours. This is an upper bound on potential recipients; Cursor does not report a count of confirmed installations or successful attacker logins.

Cursor’s original security notice identifies versions 2.1.312 and 2.1.313 for Windows and macOS, available between about 2:27am and 1:35pm Pacific on October 29. It explains that the payload installed components intended to keep remote access available, although errors and missing administrator privileges could prevent successful access. Users who installed either affected version are directed to the notice’s checks and remediation instructions. Removing the extension alone may leave persistence components behind.

Cursor says its monitoring detected the unauthorized activity. It deactivated the vendor key, revoked and rotated credentials, removed the malicious packages and temporarily took the marketplace offline. It also worked with the attacker’s hosting provider to take down the server. Some product features were interrupted while Cursor disabled services during the investigation. Team administrators received lists of exposed keys to rotate, and Cursor asked the services that issued those keys to revoke them. The company says its last observed attacker activity was blocked on November 1 and that it believes the incident is contained.

Cursor identifies Privacy Mode prompts and code, live inference traffic, customer code repositories and its production infrastructure as unaffected. It says official app releases came from a separate code host the attacker never reached and that no release-signing keys were exposed. Since the intrusion, Cursor says it has moved all inference traffic off Fireworks and ended the vendor’s access to shared datasets. It has also rotated credentials across internal systems, rebuilt the marketplace, expanded network restrictions and secret scanning, redeployed production services as a precaution, and engaged external forensic investigators.

Fireworks’ first bulletin describes unauthorized use of internal credentials detected on October 6, exposing environment variables, including stored API keys, in some customers’ evaluation jobs. Its November 9 update reports further activity: a cloud provider hosting its research machines was breached on October 23, followed by access to Fireworks development machines on October 24. Fireworks expanded the affected data categories to include account and billing information and, for some customers, datasets and incomplete model weights. It says it is working with Palo Alto Networks Unit 42 and links the activity to criminals selling unauthorized model access. Neither bulletin names Cursor, and Cursor’s update does not specify which episode exposed its key.
