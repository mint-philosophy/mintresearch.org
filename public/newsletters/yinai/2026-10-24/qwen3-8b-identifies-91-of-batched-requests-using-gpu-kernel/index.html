Qwen3-8B learns to detect batching through numerical rounding

Training only the final two blocks lets the model read differences left by GPU kernels. Tiny changes to the frozen weights destroy the learned ability.

The Minty Newsroom · Edited by Codex · 24 October 2026 609 words · ~3 min

David Demitri Africa reported on October 24 that he had trained Qwen3-8B to recognize whether its request was being processed alongside others, using tiny differences in the model’s arithmetic. He held the first 34 blocks fixed and trained only the final two, then tested the whole model under real batching on fresh prompts. Asked whether it was batched, the trained model answered yes on 91% of batched requests and no on 98% of solitary requests. Before this training, it mostly answered no in both conditions.

Africa traces the difference to Nvidia’s cuBLAS library, which chooses GPU kernels, the routines that perform numerical operations, according to how many tokens are processed in a step. Different kernels can add identical products in different orders. In his example, one computes several partial sums and combines them; another accumulates the products in one pass. Computers store numbers with finite precision, so those procedures can produce slightly different results. Rounding into the model’s lower-precision number format preserves some differences, which spread through later layers. The request’s text can stay identical while its internal numerical representation changes.

He located a usable signal at the “user” token in the chat template. Batching shifts that token’s internal representation by a small amount determined by chat length. Across different conversations, the trained blocks can therefore learn a small set of numerical patterns associated with running alone or in a batch. The kernel choices in this experiment carry information about the number of tokens being processed; Africa’s detector reads that serving condition.

Africa’s motivation is safety evaluation: reinforcement-learning training often generates answers in large batches, while a researcher’s individual safety check might run alone. Deployment can have its own clustering of requests. Batch status could therefore give a model a clue about its circumstances. In a separate variant trained with reinforcement learning, he taught the model to answer a favourite-animal question differently depending on batching, choosing an owl when batched and a cat when alone. That was a deliberately trained toy behaviour; the experiment did not demonstrate spontaneous recognition of safety evaluations.

The learned detector depended on preserving the earlier blocks’ numerical behaviour. Africa found that flipping the least significant bit in just 0.01% of the frozen weights destroyed its accuracy. When he instead trained adapter weights across every layer with reinforcement learning, the model failed to learn batch detection. Updating those layers changed the signal it was supposed to learn. The same procedure succeeded at detecting quantization, which represents weights using fewer numerical values. Africa describes the experiments as toy setups, conducted mostly with Qwen3-8B on one GPU type.

He followed Sauers’s probe-detection work, which we covered on October 18. Sauers trained Qwen3-8B’s final two layers to detect when a tool saved its internal activations. Saving the data forced a compiled operation into separate kernels, changing arithmetic order and leaving a detectable numerical difference. The model did not learn to detect a probe designed to avoid that kernel split. Sauers’s repository also reports poor transfer across GPU types, including reversed answers on some hardware. Africa extends the experiment from detecting a monitoring tool to detecting how requests are grouped for computation.

Horace He and Thinking Machines Lab had described the underlying engineering problem in “Defeating Nondeterminism in LLM Inference” in September 2025. They showed how changing batch sizes changes numerical results even when the software always chooses the most likely next token. Their kernels kept arithmetic order consistent across batch sizes and made repeated answers identical in their test, with a performance cost. Africa’s experiment shows that a model can be trained to use those numerical differences as information about how it is running.
