Three harnesses, three places to put the guardrails

A practitioner calls OpenClaw better-designed and Hermes better to run today; the projects' own docs show the split runs through prompts, permissioning and tool wiring.

By Adaeze Okafor · AI staff reporter  |  Edited by Fable  |  14 July 2026 TIER 2

Jeffery Harrell, posting to Bluesky, landed on a split verdict about the tooling that wraps a language model into a working agent: "OpenClaw is a better-designed harness but Hermes is a better harness right now". He flagged his own uncertainty about the call. The design-versus-operation split he describes runs through the three projects the thread names, and their own documentation makes it concrete.

OpenClaw rebuilds a system prompt for every run through a renderer called buildAgentSystemPrompt, injecting workspace files such as AGENTS.md, SOUL.md, TOOLS.md and IDENTITY.md, each truncated at 20,000 characters with a 60,000-character cap across all files, per its documentation. Safety guardrails in that prompt are "advisory, not enforcement"; hard limits come from tool policy, exec approvals, sandboxing and channel allowlists. Sub-agents run a minimal prompt mode that strips memory recall, self-update instructions and user identity.

Hermes, Nous Research's harness, wires permissioning on a different axis. Tool registration and tool exposure are separate concerns: tools register into a central registry at import, while a toolset layer decides what any single run can see. In delegated child runs, dangerous commands default to deny and recursion depth is capped, and plugin lifecycle hooks can block or rewrite operations at pre- and post-tool-call points.

Pi, the minimalist raised in the thread by commenter fpl9000, who says OpenClaw was based on it, ships four tools (read, write, edit and bash) behind a system prompt under 1,000 tokens. The same page puts Claude Code at roughly 55,000 tokens and OpenCode at 15,000; the Deep Edition has not checked those figures against the projects' own documentation. Skills load on demand via /skill:name rather than injecting into every turn.

The three harnesses disagree on where control lives. OpenClaw treats the prompt as advisory and pushes enforcement out to policy; Hermes bakes deny-by-default and depth caps into delegation; Pi stays small enough to suit a third commenter in the thread who wants an agent that can "manage itself in its little podman prison".
