Yesterday in AI · 29 August 2026

AgentX replays 393 real coding sessions

AgentX replays 393 anonymized Claude Code sessions as dependency graphs with subagent forks and tool-call pauses; NVIDIA has already published Vera Rubin NVL72 scores on the workload, measured by NVIDIA and pending SemiAnalysis review.

The Minty Newsroom · Edited by Codex · 29 August 2026 924 words · ~5 min

Cam Quilici, Bryan Shan, Alec Ibarra and four colleagues at SemiAnalysis argue in the AgentX 1.0 release, published on August 24, that fixed-sequence testing measures the wrong thing, because "agentic inference is inherently a systems problem". A fixed 8k-token input never lets a prefix survive to a second turn, so it exercises none of the machinery that decides agentic performance: offloading KV cache to DRAM, routing a session back to the worker holding its state, or keeping blocks alive while several sessions share them. The published matrix runs on roughly 2 megawatts of continuously operated compute, from H200 and MI300X up to GB300 NVL72 and MI355X.

SemiAnalysis built the dataset from an HTTP proxy its staff routed their own Claude Code and Codex traffic through, which has now recorded more than 8,000 sessions, 3.4 million calls and 610 billion tokens. The Hugging Face release holds a 393-session subset carrying 56,798 main turns. No original text or code survives collection: each session is tokenized, cut into 64-token blocks, and every block replaced with a session-scoped chained hash, so matching prefixes still match with nothing readable inside them. Median input per call is 142k tokens against a median output of 444, and the median pause between turns is 3.84 seconds. Subagents appear in 175 of the sessions, 1,697 rollouts in all, at a median of four per session.

Quilici asked Anthropic in April for the metadata that makes those subagent branches recoverable, filing an issue noting that parallel subagents share one session ID and cannot be told apart at a proxy. The agent and parent-agent headers shipped in Claude Code 2.1.139, which the InferenceX datasets page gives as the version floor for included sessions. With them, each session becomes a directed acyclic graph whose edges carry the recorded delay, and a subagent branch is keyed by the pair of calls that spawned and joined it. AIPerf, NVIDIA's vendor-neutral replayer, re-issues that graph from a SemiAnalysis fork. Runs warm up from a seeded point between 25% and 75% of each conversation so caches are already populated, profile for one hour, and expire idle streams after five minutes, matching Anthropic's default KV cache lifetime.

SemiAnalysis answers its own headline question model by model, and the answer moves. On GLM 5.3 at 150 tokens per second per user it reports NVIDIA holding "up to 5x better cost efficiency" on SGLang, a gap it says would survive "even if the competitor chip hardware was sold for free"; Qwen3.5 397B leaves AMD further behind, with over 20x better NVIDIA performance at 90 tokens per second per user and no AMD entry on that curve. MI355X takes performance per dollar back on Kimi K3 between 40 and 60 seconds of end-to-end latency, running AMD's own ATOM engine against GB300 NVL72 on vLLM. SemiAnalysis discounts those wins on adoption grounds, observing that AI labs "do not want to use ATOM in production" outside one Alibaba advertising unit. The DeepSeek V4 Pro ranking flipped mid-measurement: MI355X on SGLang matched B200 on vLLM for performance per dollar until August 21, when vLLM work from Inferact and NVIDIA moved B200 ahead.

The upstream changes SemiAnalysis credits to AgentX mostly repaired caches that reported themselves healthy while doing nothing. An ATOM change for DeepSeek-V4 paged sliding-window attention lifted the prefix hit rate on one trace from 5.6% to 96.45% by keeping selected window tails alive, with losses at the sliding-window gate falling from 91.35% to 0.16%, so "the cache was not missing but being overruled". An SGLang staging-buffer fix took a 127,500-token shared-prefix test from 2 correct needles out of 128 to 128 out of 128, a failure a throughput benchmark would have scored as "a fast, confident, but wrong answer". TensorRT-LLM dropped split-K MoE tactics that had crashed five of seven AgentX runs.

The authors are direct about what a replay cannot recover. Synthetic content sampled from a coding token pool would distort speculative decoding, so AgentX forces each model and speculator to an acceptance length averaged on NVIDIA's SPEED-Bench. Anthropic's proprietary tokenizer, the chat templating providers apply server side, and reasoning content that now arrives encrypted all stay invisible to the collector, which fills the gap with deterministic placeholders and calibrated per-model padding. HTTP timestamps carry timing without causality, so the replayer holds both the recorded delay and the subagent dependency where it cannot tell which produced a gap. Because the benchmark runs closed-loop, configurations complete different numbers of calls and vary most at low concurrency; NVMe offload waits for a later version, and the local generator applies the 3 TB DRAM cap to every runner. On fidelity they write that the reconstruction is imperfect, "but we can get pretty close".

NVIDIA published its own AgentX numbers the same day. In a post by Shruti Koparkar and a companion write-up by Jamie Li and Eduardo Alvarez, the company reports Vera Rubin NVL72 reaching up to 30x higher throughput per megawatt and up to 35x lower cost per million tokens than GB300 NVL72 on the AgentX DeepSeek V4 Pro workload at 160 tokens per second per user. NVIDIA took those measurements itself and labels them "currently pending SemiAnalysis review", adding that they "don't yet reflect Vera CPU performance for tool calling". SemiAnalysis has no Rubin results of its own, writing that "Rubin arrives later this month", and its visit to OpenAI's Jalapeño lab produced no AgentX runs either. AgentX ships to anyone who wants to run it; on the newest silicon, the only published scores so far come from the companies selling it.
