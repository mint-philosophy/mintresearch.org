PrismML compresses Qwen3.8 27B to 5.9 GB of language weights

The company reports 98.2% of the full-precision benchmark average. Extended coding tests retain roughly three quarters, and deployment needs additional memory and matching software.

The Minty Newsroom · Edited by Codex · 18 September 2026 1133 words · ~6 min

PrismML announced Ternary Bonsai 2 27B on September 17, bringing a compressed version of Alibaba's Qwen3.8-27B to local computers. The company reports retaining 98.2% of the original model's average benchmark score with language-model weights occupying about 5.9 GB. Its launch announcement emphasizes improved coding, image understanding and sustained tool use compared with the first Bonsai 27B. The release accepts text and images, supports a context of up to 262,000 tokens, and provides downloadable weights under Apache 2.0. PrismML demonstrated coding and computer-use workflows on an RTX 5090; its documentation also provides an Apple deployment route.

PrismML grew out of Babak Hassibi's research group at Caltech. MacKenzie Sigalos reported for CNBC in July that the university owns the underlying patents and licenses them exclusively to the company, which raised a $16.25 million seed round backed by Khosla Ventures and other investors in March. Hassibi told CNBC that Apple was evaluating the technology, describing those discussions as early. He also said factual recall tended to weaken before reasoning, mathematics and coding in the compressed models. In the September company press release, the founder and chief executive says Bonsai 2 extends the earlier model to more demanding local workflows. The release also says Google v5 TPUs were used for training.

PrismML's model card explains how the compression works. Groups of 128 weights share a 16-bit scale; each compressed weight represents minus that scale, zero or plus that scale. Nearly all the language model uses this representation, with about 0.1% of parameters retained at higher precision for recurrent state and normalization. The advertised footprint includes that exception. Image processing uses a separate component, and running a conversation requires additional memory for its cached context and intermediate calculations. The 5.9 GB figure therefore describes the compact language-model weights, not the complete memory requirement of every workload.

PrismML also changes the coordinate system in which those weights are represented. The model card describes a fixed Hadamard rotation applied before ternary compression, with a matching transformation applied to internal activity during inference. In SpinQuant: LLM quantization with learned rotations, first released on arXiv in 2024, Zechun Liu and colleagues showed how rotations can reduce extreme values that otherwise make compression inaccurate. PrismML's September whitepaper, Ternary Bonsai 2 27B: A 27B ternary reasoning model, cites SpinQuant for its fixed rotation. The released documentation specifies the resulting format and how to execute it; it does not provide a reproducible procedure for deriving the compressed weights from Qwen.

PrismML's July Bonsai 27B whitepaper explains the broader approach: start with an existing pretrained model and compress it. That differs from The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits, the 2024 arXiv report by Shuming Ma and colleagues at Microsoft Research introducing BitNet b1.58, which trained models from scratch using ternary weights. July's Bonsai used Qwen3.6-27B and retained 94.6% of its baseline average over 15 benchmarks. Bonsai 2 changes both the base model and the evaluation suite, so the improvement cannot be assigned entirely to compression. Packaging improved too: July's report listed a roughly 7.2 GB deployed ternary language model, above its 5.9 GB target.

The September whitepaper lists a compact deployed format of 5.93 GB, compared with 53.80 GB for the full-precision language model. It reports an average score of 83.9 against 85.4 over 20 benchmarks at the highest reasoning effort setting; their ratio gives 98.2%. At medium effort, retention is about 96%. Separate tests of extended coding work show larger losses: SWE-bench Verified, which tests software repair agents, falls from 80.6 to 60.8, while Terminal-Bench 2.1 also retains roughly three quarters of the baseline score. Neither coding test contributes to the headline average.

The model card's benchmark table reaches the same 98.2% through a different, 14-test selection. It includes function calling but omits the whitepaper's long-context test and simulated customer-service tasks. Both documents report company evaluations. The launch's broader claim is that compressed models can preserve useful reasoning over repeated steps, and those separate coding tests show where the measured gap remains much larger than the aggregate suggests.

For GGUF files, PrismML's demo repository requires its modified version of llama.cpp. The standard runtime lacks the matching activation transform: it rejects the two main file formats, while a development format can load and return incorrect output. The repository records upstream work in progress; support for the first Bonsai generation has already reached standard llama.cpp. The new release also omits the earlier DSpark helper model, which proposed multiple output tokens for the main model to check. That changes the available acceleration options alongside the new weight format.

Apple users can instead use the MLX package, which needs its bundled loader to apply the transformations correctly. Its instructions use standard software packages with that loader, so the llama.cpp fork requirement does not apply to every deployment. The MLX download is about 8.6 GB including its image component. Its storage layout keeps an extra number for each group of weights, adding space without changing the represented values. The smaller GGUF packing also takes more arithmetic to unpack; which format generates text faster depends on the hardware.

PrismML advertises 46.8 generated tokens per second on an M5 Max in its launch post. The model card separately labels its approximately 47-token M5 Max measurement as coming from an earlier build awaiting remeasurement. These documents leave the exact performance of the current software on that laptop unresolved. The release collection contains ternary Bonsai 2 packages; July's smaller binary variant, which the company demonstrated on an iPhone, has no Bonsai 2 counterpart there.

Developers' Hacker News reports illustrate the range of local results. Simon Willison published a working setup and timed a generated SVG of a pelican riding a bicycle at 18 minutes 20 seconds. User wombat23 reported about 41 generated tokens per second on an 8 GB RTX 3070 after changing settings that had exhausted its memory. Other users described repeated reasoning without completing longer tasks. Aurornis reported runs that consumed their output allowance in loops and judged short free-form responses more useful than coding agent work.

In a September 18 MindStudio review, Luis Chavez-Mattos tested four tasks and measured memory use. His language-model file was just over 7 GB; the process used more than 12 GB of graphics memory with four parallel request slots and about 8 GB with one. In a debugging task, the model identified a planted timezone mismatch in its reasoning, then rejected that diagnosis and changed an unrelated chart. The bug remained after more than an hour. A generated HTML animation's reset button stayed broken through three correction rounds, while an image description and creative writing task passed. Translation into Tamil became stuck in repetitive reasoning and never finished. Chavez-Mattos judged the translation result worse than his earlier tests of the previous Bonsai.
